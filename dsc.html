Unit 1

Introduction to Data Structures

📖 Definition

Data Structure is a set of procedures to define, store, access, and manipulate data. It is the logical or mathematical model of a particular organization of data.

Types of Data Structures ▾

Primitive (Elementary)

Processed as a single whole unit. Also called built-in data types.

  • Integer
  • Real / Float
  • Character
  • Boolean

Non-Primitive (Structured)

Collection of other data structures. More than one value combined under a single name.

  • Arrays
  • Stacks, Queues
  • Trees, Graphs
Linear vs Non-Linear DS ▾
FeatureLinear DSNon-Linear DS
OrderSequential, fixed orderNo fixed order
TraversalSingle run (one pass)Multiple passes needed
MemoryUsually contiguousRandom allocation
ExamplesArray, Stack, Queue, LLTree, Graph
🔑 Key Insight

In linear data structures, each element has a predecessor and a successor (except the first and last). In non-linear structures, elements can have multiple successors (e.g., tree nodes have children).

Unit 1

Arrays

📖 Definition

An array is a collection of elements of the same data type stored in contiguous memory locations, accessed using an index.

Types of Arrays ▾
1D Array (Vector)

Single row of elements. Declared as int A[20].

A[0]
A[1]
A[2]
A[i]
…
A[n-1]
2D Array (Matrix)

Rows × Columns. Declared as int M[3][4]. Stored in row-major order.

Multi-dimensional

Arrays with 3 or more dimensions. Used in scientific computing, image processing.

Address Formula — 1D Array ▾
Address of A[i]
A(i) = BA + (i − lb) × S
BA = Base Address i = Index lb = Lower Bound (0 or 1) S = Size of each element (bytes)
Array Operations & Algorithms ▾
Traverse
Visit every element once. Time: O(n)
Insertion
Shift elements right, insert at Pos. Time: O(n)
Deletion
Remove element, shift left. Time: O(n)
Search
Linear: O(n) · Binary: O(log n)
Insert Algorithm
Insert(A, N, ITEM, Pos):
  Step 1: for i = N downto Pos
             A[i+1] = A[i]   // shift right
          [end for]
  Step 2: A[Pos] = ITEM      // place item
  Step 3: N = N + 1          // increment count
  Step 4: Exit
Delete Algorithm
Delete(A, N, ITEM, Pos):
  Step 1: ITEM = A[Pos]
  Step 2: for i = Pos to N-1
             A[i] = A[i+1]   // shift left
          [end for]
  Step 3: N = N - 1
  Step 4: Exit
Advantages & Disadvantages ▾

✅ Advantages

  • O(1) random access by index
  • Cache-friendly (contiguous memory)
  • Simple to implement
  • Good for sorted data (binary search)

❌ Disadvantages

  • Fixed size (static allocation)
  • Insertion/deletion costly — O(n)
  • Memory wasted if unused
  • Homogeneous data only

Algorithms & Complexity

📖 Definition

An algorithm is a finite, well-defined sequence of steps to solve a problem. Analysis of algorithms helps us predict performance before implementation.

Characteristics of a Good Algorithm ▾
Input

Zero or more well-defined inputs

Output

At least one output produced

Definiteness

Each step must be clear & unambiguous

Finiteness

Must terminate after finite steps

Effectiveness

Steps must be basic & feasible

Asymptotic Notations ▾
O
Big-O (Upper Bound)

f(n) = O(g(n)) — worst case. The function never grows faster than g(n) beyond some n₀.

Ω
Omega (Lower Bound)

f(n) = Ω(g(n)) — best case. The function always grows at least as fast as g(n).

Θ
Theta (Tight Bound)

f(n) = Θ(g(n)) — average case. Both upper and lower bounds are g(n).

Order of Growth (Best → Worst) ▾
O(1)ConstantArray access
O(log n)LogarithmicBinary search
O(n)LinearLinear search
O(n log n)Log-linearMerge sort
O(n²)QuadraticBubble sort
O(n² log n)Poly-logComplex loops
O(2ⁿ)ExponentialBrute-force TSP
💡 Tip — How to Calculate T(n)

Count each type of operation separately, then take the dominant term:

T(n) = O(1) + O(n) + O(n) + O(log n) + O(n² log n)
     ≈ O(n² log n)   ← dominant term wins
🔑 Key Summations
Σi = n(n+1)/2
Σi² = n(n+1)(2n+1)/6
Σ2ⁱ = 2ⁿ⁺¹ − 1

Linked Lists

📖 Definition

A linked list is a dynamic data structure where each element (node) contains data and a pointer to the next node. Nodes need not be contiguous in memory.

Node Structure ▾
DATA
NEXT →
→
DATA
NEXT →
→
DATA
NULL
C Structure
struct stud {
  int roll;
  char name[30];
  int age;
  struct stud *next;  // self-referential
};
Linked List vs. Array (Comparison) ▾
OperationArrayLinked List
Access by indexO(1)O(n)
Insert at beginningO(n)O(1)
Insert at endO(1)*O(n)
Delete any elementO(n)O(n)**
Memory allocationStatic (fixed)Dynamic (flexible)
SearchO(n) linearO(n) sequential

* If array isn't full. ** O(1) if pointer to node given.

Operations ▾
Insertion at Beginning
  1. Create new node
  2. Set new_node→next = head
  3. Set head = new_node
newNode->next = head;
head = newNode;
Insertion at End
  1. Create new node, set next = NULL
  2. Traverse to last node (temp→next == NULL)
  3. Set last_node→next = new_node
Deletion at Beginning
  1. Check if list is empty
  2. Store head in temp
  3. Move head = head→next
  4. Free(temp)
Search (Linear)

Traverse from head; compare each node's data with key. Return node if found, NULL otherwise. Time: O(n).

Types of Linked Lists ▾
Singly Linked List

Each node has one pointer (next). Traversal only forward. Most basic type.

Doubly Linked List

Each node has two pointers: prev and next. Can traverse both directions.

Circular Linked List

Last node points back to first node. Useful for looping/round-robin applications (media players, OS scheduling).

💡 Real-World Applications
  • Browser history (Back/Forward buttons)
  • Music player playlists
  • Image viewer (previous/next)
  • Implementation of stacks and queues
  • Dynamic memory allocation free blocks
  • Polynomial manipulation

Stacks

📖 Definition

A stack is a linear data structure that follows the LIFO (Last In, First Out) principle. The element inserted last is the first to be removed.

Stack Visualization ▾
TOP →
40 ← Last In
30
20
10 ← First In

PUSH adds to TOP · POP removes from TOP

Operations & Algorithms ▾
PUSH (Insert)
Push(S, Top, X, N):
  If Top = N-1 then
    write "Stack FULL"
    exit
  Top = Top + 1
  S[Top] = X
  Exit
POP (Delete)
Pop(S, Top):
  If Top = -1 then
    write "Stack EMPTY"
    exit
  X = S[Top]
  Top = Top - 1
  return X
Boundary Conditions

Overflow: Top = N−1 (push on full stack)  |  Underflow: Top = −1 (pop on empty stack)

Applications of Stack ▾
Expression Evaluation

Postfix expression evaluation. No need for parentheses or operator precedence rules during execution.

Infix → Postfix Conversion

Operator precedence: ^ > * / > + -. Use stack to hold operators until appropriate.

Function Call Stack

OS uses stack for function calls, recursion, return addresses.

Undo/Redo

Text editors use two stacks — one for undo operations, one for redo.

💡 Postfix Evaluation Algorithm
  1. Scan expression left-to-right
  2. If operand → PUSH onto stack
  3. If operator → POP two operands (A = top, B = second)
  4. Evaluate B operator A, PUSH result
  5. Final result = POP

Example: 2 3 1 * + 9 - → 2 + (3×1) − 9 = −4

Queues

📖 Definition

A queue is a linear data structure that follows the FIFO (First In, First Out) principle. It is open at both ends: insertion at REAR, deletion at FRONT.

Queue Visualization ▾
FRONT
10
20
30
40
REAR

ENQUEUE at REAR · DEQUEUE from FRONT

Operations ▾
ENQUEUE
Enqueue(Q, REAR, X, N):
  If REAR = N-1 then
    write "Queue FULL"
    exit
  If FRONT = -1 then
    FRONT = 0
  REAR = REAR + 1
  Q[REAR] = X
DEQUEUE
Dequeue(Q, FRONT, REAR):
  If FRONT = -1 OR
     FRONT > REAR then
    write "Queue EMPTY"
    exit
  X = Q[FRONT]
  FRONT = FRONT + 1
  return X
Types of Queues ▾
Simple Queue

Basic FIFO. Linear array. Problem: front pointer never resets → wasted space.

Circular Queue

Front and rear wrap around. Solves wasted-space problem. REAR = (REAR+1) % N

Double-Ended Queue (Deque)

Insertion and deletion at both ends. More flexible than simple queue.

Priority Queue

Each element has priority. Higher-priority element dequeued first regardless of insertion order.

Trees & Binary Search Trees

📖 Definition

A tree is a non-linear, hierarchical data structure with a root node and subtrees of children nodes. A Binary Search Tree (BST) satisfies: left child < parent < right child.

Key Terminology ▾
Root

Topmost node, no parent. Entry point of the tree.

Leaf Node

Node with no children. Also called external node.

Height

Longest path from root to a leaf. Empty tree height = −1.

Depth

Distance from root to that node.

Degree

Number of children a node has.

Subtree

Any node with its descendants forms a subtree.

BST Operations ▾
Search
Compare with root → go left if smaller, right if larger. Best: O(log n), Worst: O(n)
Insert
Like search, find correct leaf position, insert new node. O(h) where h = height.
Delete
3 cases: leaf node (just remove), one child (bypass), two children (replace with inorder successor).
Tree Traversals ▾
Inorder (L → Root → R)

Visits BST nodes in sorted ascending order. Used to verify BST property.

Preorder (Root → L → R)

Root visited first. Used to copy/serialize a tree structure.

Postorder (L → R → Root)

Root visited last. Used to delete a tree (children first).

Level-order (BFS)

Visit level by level. Uses a queue. Used for level-wise operations.

🔑 Memory Aid

Inorder → Increasing (sorted) · Preorder → Preserves structure · Postorder → Post-mortem (delete)

Unit 4

AVL Trees

📖 Definition

An AVL Tree (Adelson-Velsky and Landis, 1962) is a self-balancing BST where the Balance Factor of every node must be −1, 0, or +1.

Balance Factor
BF = Height(Left Subtree) − Height(Right Subtree)
BF = 0 → Balanced BF = ±1 → Acceptable BF = ±2 → UNBALANCED → Rotate
4 Rotation Cases ▾
LL Rotation
Imbalance in left subtree of left child
→ Single Right rotation at pivot
RR Rotation
Imbalance in right subtree of right child
→ Single Left rotation at pivot
LR Rotation
Imbalance in right subtree of left child
→ Left rotation on child, then Right rotation at pivot
RL Rotation
Imbalance in left subtree of right child
→ Right rotation on child, then Left rotation at pivot
AVL vs BST Performance ▾
OperationBST (worst)AVL Tree
SearchO(n)O(log n)
InsertO(n)O(log n)
DeleteO(n)O(log n)
SpaceO(n)O(n)
💡 Practice Sequence

Build AVL tree for: 5, 7, 19, 12, 10, 15, 18, 20, 25, 23 — apply rotations step by step. Check balance factor after each insertion.

Graphs

📖 Definition

A graph G = (V, E) consists of a set of vertices V and edges E. Edges represent relationships between vertices. Graphs model networks, maps, social connections, etc.

Graph Terminology ▾
Directed Graph (Digraph)

Edges have direction (arrows). Edge (u,v) ≠ Edge (v,u).

Undirected Graph

Edges have no direction. Edge (u,v) = Edge (v,u).

Weighted Graph

Each edge carries a numerical value (weight/cost).

Degree of Vertex

Undirected: number of edges incident. Directed: in-degree + out-degree.

Path

Sequence of vertices where consecutive pairs are connected by edges.

Cycle

A path that starts and ends at the same vertex. A tree has no cycles.

Connected Graph

Every vertex is reachable from every other vertex (undirected).

Complete Graph

Every vertex is directly connected to every other vertex. Edges = n(n-1)/2.

Graph Representations ▾

Adjacency Matrix

n×n matrix where M[i][j] = 1 if edge (i,j) exists, 0 otherwise.

Space: O(n²) · Edge check: O(1)

✅ Fast lookup · ❌ Wastes space for sparse graphs

Adjacency List

Array of linked lists. Each vertex has a list of its neighbors.

Space: O(V+E) · Edge check: O(degree)

✅ Efficient for sparse graphs · ❌ Slower edge lookup

Number of Edges
Undirected: max edges = n(n−1)/2
Directed: max edges = n(n−1)
Graph Traversals ▾

BFS — Breadth First Search

Explores all neighbors at current depth before going deeper. Uses a Queue.

Time: O(V+E) · Use: shortest path, level-order, connected components

DFS — Depth First Search

Explores as far as possible before backtracking. Uses a Stack (or recursion).

Time: O(V+E) · Use: topological sort, cycle detection, maze solving

Dijkstra's Algorithm

📖 Definition

Dijkstra's algorithm solves the Single-Source Shortest Path problem on a weighted graph with non-negative edge weights. It finds shortest paths from source vertex v to all other vertices.

Algorithm Pseudocode ▾
Dijkstra(G, source)
for each vertex v:
    v.distance = ∞
    v.previous = NONE
source.distance = 0
List = {all vertices}       // unvisited set

while List is not empty:
    v = vertex in List with min distance
    mark v as known (remove from List)

    for each unknown neighbor n of v:
        dist = v.distance + weight(v, n)
        if dist < n.distance:
            n.distance = dist
            n.previous = v

return distances and path via previous pointers
Key Properties ▾
Greedy Approach

Always picks the unvisited vertex with the minimum known distance.

Works On

Both directed and undirected graphs. Requires non-negative weights.

Output

Shortest distances from source to all vertices + path reconstruction via previous pointers.

Applications

Google Maps, GPS routing, network packet routing (OSPF protocol).

Time Complexity ▾
ImplementationTime Complexity
Array / Linked List (simple)O(V²)
Binary Heap + Adjacency ListO((V + E) log V)
Fibonacci HeapO(E + V log V)
💡 Why Non-Negative Weights?

If negative edges exist, a previously "finalized" vertex might get a shorter path discovered later, breaking the greedy guarantee. Use Bellman-Ford for negative weights.

Practice Questions & MCQs

Solved Problems
Problem 1 — Postfix Evaluation

Q: Evaluate the postfix expression: 2 3 1 * + 9 -

1 Scan 2 → Push → Stack: [2]
2 Scan 3 → Push → Stack: [2, 3]
3 Scan 1 → Push → Stack: [2, 3, 1]
4 Scan * → Pop 1, Pop 3 → 3×1=3 → Push → Stack: [2, 3]
5 Scan + → Pop 3, Pop 2 → 2+3=5 → Push → Stack: [5]
6 Scan 9 → Push → Stack: [5, 9]
7 Scan - → Pop 9, Pop 5 → 5−9=−4 → Result: −4
Problem 2 — Array Address Calculation

Q: Array A starts at address 200. Each element is 4 bytes. Find address of A[6], with lower bound = 0.

Formula A(i) = BA + (i − lb) × S
Apply A(6) = 200 + (6 − 0) × 4 = 200 + 24 = 224
Problem 3 — AVL Insertion

Q: Insert 30, 20, 10 into an empty AVL tree.

1 Insert 30 → Root. BF=0 ✓
2 Insert 20 → Left of 30. BF(30)=1 ✓
3 Insert 10 → Left of 20. BF(30)=2 ✗ → LL Case!
Fix Right rotate at 30 → 20 becomes root, 10=left, 30=right. All BF=0 ✓
