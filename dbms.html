1. Introduction to DBMS

Definition & Basics

A Database Management System (DBMS) is software designed to store, retrieve, define, and manage data in a database.


Data vs Information

  • Data: Raw, unorganized facts (e.g., "100", "John").
  • Information: Processed data that carries meaning (e.g., "Student John scored 100").

Advantages of DBMS

  • Controls database redundancy
  • Data sharing and integration
  • Enforces data security and integrity
  • Data consistency

Features of DBMS

  • Data Security: Protection against unauthorized access.
  • Reduced Redundancy: Eliminates duplicate data.
  • Data Consistency: Ensures data is accurate across all tables.
  • Multi-user Access: Concurrent access without data loss.

Types of DBMS

  • Hierarchical: Tree-like structure (Parent-Child).
  • Network: Graph structure allowing complex relationships.
  • Relational (RDBMS): Data stored in tables (Rows/Columns). Most common.
  • Object-Oriented: Data stored as objects, similar to OOP.

2. Normalization

Definition & Purpose

Normalization is the process of organizing data to minimize redundancy and eliminate insertion, update, and deletion anomalies. Purpose: Reduce redundancy and improve data consistency.

First Normal Form (1NF)

A table is in 1NF if it contains only atomic (indivisible) values. There are no repeating groups or arrays.

Second Normal Form (2NF)

Must be in 1NF. All non-key attributes must be fully functionally dependent on the primary key. (Removes partial dependency).

Third Normal Form (3NF)

Must be in 2NF. There should be no transitive dependency (non-key attributes should not depend on other non-key attributes).

Boyce-Codd Normal Form (BCNF)

A stricter version of 3NF. For every functional dependency X → Y, X must be a super key.

3. SQL Commands

Data Definition Language (DDL)

Defines the database structure or schema.

  • CREATE: Creates a new table/database.
  • ALTER: Modifies structure.
  • DROP: Deletes table structure and data.
CREATE TABLE Student(
   ID INT PRIMARY KEY,
   Name VARCHAR(20)
);

Data Manipulation Language (DML)

Manages data within schema objects.

  • INSERT: Adds new rows.
  • UPDATE: Modifies existing rows.
  • DELETE: Removes rows.
INSERT INTO Student (ID, Name) 
VALUES (1, 'Alice');

UPDATE Student SET Name = 'Bob' 
WHERE ID = 1;

DQL & TCL

DQL (Data Query Language): Used to fetch data.

SELECT * FROM Student;

TCL (Transaction Control Language): Manages transactions.

  • COMMIT: Saves work permanently.
  • ROLLBACK: Restores database to last commit.

4. Keys & Relationships

Database Keys

  • Primary Key: Uniquely identifies each record in a table. Cannot be NULL.
  • Foreign Key: A key used to link two tables together; refers to the PK of another table.
  • Candidate Key: A set of attributes that can uniquely identify a tuple. A table can have multiple.
  • Super Key: A set of one or more attributes which can uniquely identify a row.
  • Composite Key: A primary key consisting of more than one attribute.

Table Relationships

One-to-One (1:1)

One record in Table A is linked to exactly one record in Table B. (e.g., User and UserProfile).

One-to-Many (1:N)

One record in Table A relates to multiple records in Table B. (e.g., Department and Employees).

Many-to-Many (M:N)

Multiple records in Table A relate to multiple records in Table B. Requires a junction table. (e.g., Students and Courses).
